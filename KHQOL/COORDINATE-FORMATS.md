# 1.11.8.24 ForeverNote 좌표 형식·우선순위

사용자 입력은 0~100 백분율입니다. 내부 AddTodoCoordinate(mapID,x,y,label)는 0~1 정규화 좌표 API이며 구분해서 한 번만 변환합니다. `0.465`를 입력하면 0.465%이고 내부 값은 0.00465입니다.

```text
잿빛 골짜기 46 73 메모
잿빛 골짜기 46.5 73.2 메모
잿빛 골짜기 46,73 메모
잿빛 골짜기 46, 73 메모
잿빛 골짜기 46 ,73 메모
잿빛 골짜기 46 , 73 메모
잿빛 골짜기 46.5, 73.2 메모
가시덤불 골짜기 29, 75 무법항
1440 46.5, 73.2 메모
#1440 46.5, 73.2 메모
/way #1440 46.5, 73.2 123, 메모
/way 46,73 현재 지역 메모
희귀몹 확인 @46,73
/nt way 잿빛 골짜기 46.5,73.2 메모
/노트 way #1440 46.5 73.2 메모
```

예시 지도 ID도 클라이언트가 실제로 같은 지도를 제공할 때만 등록됩니다. 지역명은 클라이언트 이름에 맞게 공백을 정규화해 찾고, 같은 이름의 지도가 여럿이면 거부합니다. 미확인 지도를 다른 지도나 현재 지역으로 대체하지 않습니다.

| 입력 경로 | 해석 우선순위 |
|---|---|
| `#mapID X Y 메모` 또는 쉼표 | 항상 명시한 지도. 실패하면 중단 |
| 노트의 일반 지역/지도 입력 | 검증된 지역명 또는 숫자 지도 ID가 필요. 맨 앞 유효한 좌표 뒤는 그대로 메모 |
| `/nt way` / `/노트 way`의 선두 세 숫자 | 기존처럼 지도 ID·X·Y 우선. 좌표 범위 오류는 현재 지도 메모로 바꾸지 않음 |
| 노트 안 `/way X Y 123 메모` | 기존처럼 현재 지역 X·Y + 숫자로 시작하는 메모 우선 |
| 노트 안 `/way 1440 X Y 메모` | 첫 숫자가 좌표로 성립하지 않으면 유효한 지도 ID로 해석 가능. 모호성 방지를 위해 #mapID 권장 |
| `메모 @X,Y` | 기존 현재 지역 후행 형식. 유효한 선두 지역/지도 좌표가 있으면 뒤의 @ 표기는 메모로 보존 |

지역을 생략하는 `/way`·`@`·명령 경로는 현재 플레이어 지도 조회와 지도 유효성 확인이 필요합니다. 일반 노트의 `46,73 메모`만으로는 좌표를 만들지 않습니다. 숫자로 시작하는 메모가 있으면 `/nt way #1440 46 73 123 메모`처럼 지도를 명시하세요. 전역 `/way` 명령은 등록/덮어쓰지 않으며 노트 문자열 안에서만 읽습니다.

정수와 소수점 .만 지원합니다. 좌표를 벗어난 쉼표는 치환하지 않습니다. Y와 메모 사이에는 공백이 필요하며 `46,73메모`·음수·100 초과·중복 쉼표·누락·문자 좌표·미확인/중복 지도는 좌표가 아닙니다. 메모의 내부 공백·한글·숫자·쉼표·특수문자는 보존하고 기존처럼 양끝 공백만 정리합니다. 빈 좌표 메모는 ‘노트 위치’입니다.

체크리스트는 원문과 체크 상태/ID를 유지합니다. 잘못된 좌표는 waypoint가 없는 일반 메모로 저장하며 다른 메모 저장을 막지 않습니다. 기존 문자열을 일괄 재작성하지 않습니다. 사용자가 새로 입력/수정한 항목에만 파싱을 적용합니다. 명시적 명령 실패는 기존 사용법/오류 메시지와 원문 메모리 보존을 사용하며 채팅 입력을 다른 명령으로 바꾸지 않습니다. 입력 파서/명령 길이는 2048바이트, 구조화 등록 메모는 기존 512바이트·한 줄 제한입니다.

AddTodoCoordinate는 지도 유효성·정규화 단위를 확인하고 전용 좌표 체크리스트만 재사용합니다. 같은 지도·기존 소수점 5자리 백분율 좌표·같은 정리된 메모이면 기존 객체와 duplicate를 반환합니다. 완료 상태·사용자 메모를 덮어쓰지 않습니다. 메모가 다르면 별도 항목을 만들 수 있습니다. 직접 체크리스트 입력은 기존 저장 정책을 유지합니다. 새 성공은 기존 RefreshTodo/Navigation/지도 핀 경로를 사용하고 강제 수동 길 안내를 시작하지 않습니다.
