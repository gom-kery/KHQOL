## 설정창 성능 근거

이전1.11.9.2는 사거리 설정창이 열린 동안 모든 GET_ITEM_INFO_RECEIVED/ITEM_DATA_LOAD_RESULT를 전체 UpdateSettings로 연결했다. 사거리와 무관한 ID도 구분하지 않았다. 전체 Refresh는 글꼴/값/배치 재계산을 반복했다. 대상이 없는 첫5~10초에만 발생한다는 제보는 초기 자료 로딩 집중과 부합하지만, 발생 당시 인게임 이벤트/CPU를 직접 기록하지 않았으므로 원인 전체를 확정한 것은 아니다.

| 모의 조건 | 결과 |
| --- | --- |
| 이전본: 대상 없음·창 열림·무관한 아이템 알림40회 | 전체 설정 갱신40회 / 배치 재계산240회 |
| 수정본: 같은 조건·무관한 알림80회 | 전체 설정/재배치/거리 표시 갱신0회 |

이는 호출 횟수 모의 검사이며 실게임 FPS 향상률이나5~10초 렉 완전 해소를 실측한 수치는 아니다. 초기 설정 페이지 생성 비용 자체와 다른 애드온의 부하는 별개다. 새 반복 갱신기/백그라운드 작업을 추가하지 않았다. 사거리0.08초 기존 표시 주기는 유지한다.

## 기본 버프·음식·침낭 사용

버프 리마인더를 켜고 직업을 고르면 기본 버프 항목에 포만감/충분한 휴식이 제공된다. 기존 수동 buffs 배열을 덮어쓰거나 순서를 바꾸지 않았다. 같은 공개 포만감 이름/확인ID와 충분한 휴식429959가 수동 목록에도 있으면 기본 감시가 켜진 동안 중복 표시를 줄인다.

포만감은 실제 공개된 오라 이름/검증된 효과를 기준으로 확인한다. 과거 후보1249519는 이름이 포만감/Well Fed로 확인될 때만 이미지 후보로 사용하고, 실제 관찰한 오라 아이콘을 우선한다. 이를 모든 음식의 실제 SpellID라고 가정하지 않는다. 오라를 읽을 수 없으면 부재로 단정하지 않는다.

음식 알림은 기존 ON/OFF·자동/지정 선택을 유지한다. 기존OFF를 강제로 켜지 않았다. 활성화한 음식 알림의 위/아래 위치를 고른다. 실제 식사 시작과 선택 음식의 검증된 필요 초로 진행을 표시한다. 사용자 제보4592는10초다. 다른 음식의 미확인 필요 시간을 임의10초로 만들지 않는다. 직접 클릭 없는 가방 사용/리로드의 시각 복원은 사용 성공 통계로 귀속하지 않는다.

충분한 휴식429959가 없고 가방의211527 보유량이 확인된 캐릭터에만 침낭 사용 아이콘이 나온다.133662 이미지와 사용자가 제공한 ID를 사용했다. 재고는 가방/잠금 이벤트와 최초 활성화 때 확인하며 매 프레임 순회하지 않는다. 없거나 재고가 미확인이면 사용 아이콘을 숨긴다. 기본 휴식 버프 감시 항목과 보유 조건이 있는 침낭 사용 아이콘은 구분된다. 실제 사용은 잠긴 비전투 아이콘 직접 클릭이며 자동 사용하지 않는다. 전투 중 사용/편집 가림과 기존 secure action identity/위치 보존을 유지한다.

## 설정 진입·전문기술

휴지통 우클릭은 공통 페이지에 들어가 가방 휴지통 외의 아코디언을 접는다. 크기 컨트롤은 직접 숫자 상자를 고정 좌표에 놓던 방식을 버리고 FitSlider/AnchorToSlider로 트랙·화살표·현재 값 폭을 맞춘다. 좌클릭 아이템 파괴·보호/확인 정책은 유지한다.

전문기술 텍스트 우클릭은 해당 설정으로 이동한다. 전문기술 아이콘의 우클릭 등록 지원은 기본이며 옛 rankGuide.notes=false도 등록을 막지 않는다. 옛 저장 필드와 통계 정의는 호환용으로 보존하지만 UI는 제거한다. 다음 단계 안내/습득 위치 표시의 기존 사용 선택은 유지한다. 장소 안내가 나오는 상태여야 기존 한 곳 즉시/두 곳 선택 등록을 사용한다. 좌표 미검증·노트 미설치/비활성·전투·단계/진영/프로필 변경·중복 정책은 보존하고 기존 메모를 덮어쓰지 않는다.

## 전문화 API 조사

[Forever C_SpecializationInfo 추출 자료](https://raw.githubusercontent.com/Atraeau/WoW-Addons/main/docs/api/Spells-Auras-Talents/C_SpecializationInfo.md)에서 GetSpecializationInfo의 pointsSpent, GetInspectSpecialization, 구조화된 GetTalentInfo(query)의 rank와 inspect target 필드를 확인했다. 로컬 Blizzard PlayerSpells 소스도 살펴보기 선택 전문화ID 경로를 사용한다. 해당 추출 빌드는70790이며 사용자70959에서 서버가 데이터를 실제 반환한다는 보증은 아니다.

기존 NotifyInspect → INSPECT_READY의 GUID 소유권·재시도/간격/timeout·수동 살펴보기 보호를 유지했다. 기존 포인트 조회가0/미확인인 경우 레거시 탭/랭크·구조화된 조회를 대조하고, 완전한 분포가 없으면 선택ID/선택 인덱스에서 확인되는 이름만 사용한다. 잘못된0/0/0 분포를 붙이지 않는다.

[C_Traits 추출 자료](https://raw.githubusercontent.com/Atraeau/WoW-Addons/main/docs/api/Spells-Auras-Talents/C_Traits.md)의 GetConfigInfo/GetTreeNodes/GetNodeInfo는 configID 문맥이 필요하다. 검증된 상대 configID 획득 경로 없이 자신의 config를 상대 특성으로 읽는 방식은 적용하지 않았다. API가 존재한다는 사실과 서버가 상대 데이터를 제공한다는 사실을 구분했다.

실제 확인 방법: 툴팁 플레이어 정보를 켜고 살펴보기 가능한 아군 플레이어의 툴팁을 띄워 응답을 기다린 뒤 /khqolspec을 입력한다. 지원 API와 최근 조회 경로(talent-points/inspect-specialization-id/inspect-selected-index/unavailable 등)를 출력한다. 명령 자체는 새 살펴보기·반복 조회를 시작하지 않으며 개인/대상/특성 수치를 기록하지 않는다. 현재 서버에서 계속 응답을 못 받는지의 최종 판정은 인게임 NOT TESTED다.
