## 전투 종료 작업 축소

파티·공격대는 보류된 변경이 없는데도 매 전투 종료에 45개의 보관된 버튼을 꾸미고 9개 그룹의 표시 조건·휠 설정을 다시 적용했습니다. 이제 변경이 없으면 이를 생략하며 역할 프로필·그룹/공격대 규모·기본 프레임 소유권을 확인합니다. 실제 변경이 있으면 최신 값으로 전체 적용합니다. 보류 작업은 공용 처리기에 맡겨 이벤트 처리 순서가 달라도 중복 실행하지 않습니다. 실패 후 기본 프레임 복원/외부 소유권 양보도 유지하고 같은 종료 처리에서 다시 시도하지 않습니다. 설정·로드/주문 이벤트의 재요청은 가능합니다.

전체 파티 적용의 RefreshAll과 ConfigureEvents 양쪽에서 버튼 이벤트를 다시 등록하던 처리를 한 번으로 줄였습니다. 보이는 버튼 수에 따라 실제 이벤트 등록 횟수는 달라집니다.

유닛 프레임은 체력 표시 가시성·글자 스타일의 전투 보류를 전체 배치 변경과 구분합니다. 종료 시 가벼운 값·상태 표시 복원을 사용하며 토템·포만감 위치 복원도 실행합니다. 전투 중 실제 배치 변경, 모듈 OFF, 보호된 토템 이동, 공개 속성 읽기/복원 실패는 전체 적용을 유지합니다.

동기 설정/유닛 적용 안에서는 한 번 정규화한 DB를 재사용해 하위 함수마다 전체 기본값 검사를 반복하지 않습니다. 범위는 그 호출 안으로 제한되며 예외/종료 시 해제합니다. 프로필 세대·DB/설정 테이블이 바뀌면 이전 참조를 사용하지 않습니다. 새 저장 필드는 없습니다.

## 기본 UI 잡템 일괄 판매

기준 버전은 슬롯별 확인 기반 개별 판매였습니다. 이제 게임의 IsSellAllJunkEnabled가 참이고 GetNumJunkItems/SellAllJunkItems가 있으면 **기본 C_MerchantFrame 일괄 판매**를 상점 방문당 한 번 호출합니다. 대상 판단은 게임 엔진에 맡기며 애드온의 가방 순회·슬롯별 판매를 병행하지 않습니다. 기본 기능이 미지원인 경우에만 기존 개별 큐를 사용합니다. [클라이언트 API 정의](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/MerchantFrameDocumentation.lua).

일괄 요청은 반환값으로 성공을 단정하지 않습니다. 남은 잡템 수와 가방 이벤트/0.05초 확인으로 완료를 판단하고 2초 기한을 넘으면 중단합니다. 요청 이후 오류·응답 지연에는 재시도나 개별 큐 전환을 하지 않아 중복 판매를 막습니다. 상점 닫기·옵션 OFF·옛 예약 콜백을 검사합니다. 확인된 완료 후 기존 자동 수리 판단을 한 번 수행합니다. 판매 속도는 실제 클라이언트·서버 응답에 따릅니다.
