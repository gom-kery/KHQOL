# KHQOL 1.11.9.8 버프 드래그 등록

## 기준과 사용

최신 작업본 1.11.9.7을 기준으로 수정했습니다. 직전 전체 설치 ZIP을 baseline97과 파일별 SHA-256으로 대조하고 보존합니다.

1. 편의 기능 > 버프 리마인더 > 버프 등록에서 직업을 선택합니다.
2. 마법책의 주문을 입력란, 버프 추가 버튼 또는 같은 등록 행의 빈 부분에 끌어 놓습니다.
3. 선택한 직업 목록에 바로 추가됩니다. 추가 버튼을 한 번 더 누르지 않아도 됩니다.

기존 Spell ID/주문 이름 직접 입력도 유지합니다. 목록·행 툴팁·삭제 확인에는 레벨/등급을 뺀 이름을 사용합니다. 예: `얼음 갑옷 (1레벨)` → `얼음 갑옷`. 기존 진단용 주문 ID는 별도로 표시합니다.

## 구현 범위

- BuffReminder/Settings.lua: 입력란·추가 버튼·등록 행의 OnReceiveDrag를 동일 등록 경로에 연결했습니다. 드래그와 직접 입력은 같은 중복 검사/기본값/목록 갱신 경로를 사용합니다.
- BuffReminder/Core.lua: 표시/입력용 이름 정리를 추가했습니다. 한국어 숫자 레벨·등급, 영어 Rank 숫자 등의 끝 괄호만 제외합니다. `방어 (냉기)`와 의미 있는 괄호는 보존합니다.
- 주문 이름을 SavedVariables에 새로 저장하지 않습니다. 기존 `spellID`, `enabled`, `displayMode` 구조를 그대로 사용합니다. 드래그한 주문의 실제 ID를 저장하며 임의의 다른 등급 ID로 치환하지 않습니다.
- 버프 판정과 시전용 GetSpellDetails 이름은 원본 그대로 사용합니다. 표시 이름 정리가 오라 조회·시전 동작에 영향을 주지 않도록 분리했습니다.
- 커서의 네 번째 반환값인 Spell ID를 확인합니다. 두 번째 반환값은 마법책 슬롯일 수 있으므로 주문 ID로 추측하지 않습니다. ID와 클라이언트의 주문 정보를 확인할 수 없으면 거부합니다.
- 등록 성공 시에만 ClearCursor를 호출합니다. 중복 ID, 아이템/매크로, 누락·음수·소수·비공개 ID, 주문 정보 로딩 실패 시 기존 입력·목록·커서를 보존합니다.
- 전투 중에는 등록하지 않고 종료 후 등록하도록 안내합니다. 모듈 OFF에도 등록하지 않습니다. 마법책/보호된 Blizzard 프레임이나 전역 함수를 변경하지 않았습니다.
- DevTools 0.3.11과 통계 카탈로그는 원본 그대로 유지합니다. 동적 등록 주문명·ID를 Usage Analytics의 새 수집 값으로 추가하지 않았습니다.
