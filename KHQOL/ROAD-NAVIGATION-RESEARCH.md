# KHQOL 1.11.5.8 — 도로 기반 자동 길찾기 기술 검토와 후속 계획

조사일: 2026-10-21. 기준 소스: KHQOL 1.11.5.7. **본 문서는 설계이며 1.11.5.8에 자동 도로 탐색 코드를 넣지 않았습니다.** 현재 기능은 사용자가 지정한 경유지를 순서대로 연결하고 안내합니다.

## 조사 결론

사전에 검증한 도로 그래프를 별도로 확보한다면 구현할 수 있습니다. 가장 큰 선행 과제는 탐색 알고리즘보다 **Forever의 실제 통행 가능성과 일치하는 연결 데이터**입니다. 지도에 그려진 길과 지형 이미지에서 애드온이 도로 연결·높이·충돌 정보를 직접 읽을 수 있다고 가정하지 않습니다.

확인한 공개 Forever 분기의 Map·TaxiMap·Minimap 명세와 기존 지도 UI 소스에서, 애드온이 사용할 수 있는 완전한 보행 도로 그래프·navmesh·위험도 지도를 반환하는 계약은 확인하지 못했습니다. 이는 모든 내부 API가 없다는 단정이 아닙니다. 실행 중인 클라이언트에서의 공개 여부와 정확도는 **인게임 검증 필요**입니다.

자료 확보 방식은 작은 지역의 수작업 도로 조사부터 시작하는 것이 현실적입니다. 외부 공개 데이터는 사용 허가·재배포 권한·좌표계·클라이언트 빌드를 확인해야 합니다. 이용자 이동 기록은 도로 후보를 만드는 데 쓸 수 있지만, 비행/수영/낙하/층 차이가 섞이므로 기록만으로 양방향 도로 연결을 확정할 수 없습니다. 비공개 클라이언트 메모리 접근이나 실행 파일 변조는 제안하지 않습니다.

## 그래프 구조 제안

원래 노트 핀과 별개인 읽기 전용 도로 데이터로 구성합니다. 계산된 결과는 기존 경유지 안내에 전달하고, 기존 노트·프로필·화살표 엔진은 재사용합니다.

```text
Dataset: version, verifiedClientBuild, coordinateSystem, license, coverage
Node: id, mapID, worldID, layerID, x, y, kind
Edge: from, to, distanceYards, travelTime, kind, direction, requirements,
      riskDataID, confidence, verifiedBuild
Kinds: road / bridge / mountainPass / border / flight / boat / portal
```

같은 world와 층 안에서도 실제 통행을 확인한 간선만 연결합니다. 지역 경계는 각 지역의 좌표를 같은 world 기준으로 변환한 후 **연결 지점을 조사해** 묶습니다. 다른 대륙·인스턴스는 자동 직선으로 잇지 않고 검증된 특수 이동 간선으로만 연결합니다. 목적지와 가까운 그래프 노드도 절벽 반대편이나 동굴 위층일 수 있으므로, 단순 최근접 검색만으로 진입 가능성을 보장하지 않습니다. 그래프에 연결할 수 없는 출발/목적지는 수동 경유지로 보완합니다.

## A*와 Dijkstra 비교

| 방식 | 장점 | 조건과 부담 |
| --- | --- | --- |
| Dijkstra | 음수가 아닌 비용에서 기준 결과를 얻기 쉬움. 특수 이동 포함 검증 기준으로 적합 | 후보가 많으면 넓게 탐색. 이진 힙 구현 시 O((V+E) log V), 탐색 상태 O(V) |
| A* | 유효한 휴리스틱이 있으면 일반적인 목적지 검색에서 탐색량을 줄일 여지가 있음 | 최단 경로 조건을 위해 비용의 하한인 휴리스틱 필요. 잘못된 휴리스틱이면 결과 보장이 깨짐. 최악의 탐색량은 여전히 큼 |

도보 거리 비용만 사용한다면 같은 좌표계의 직선 거리를 하한 후보로 검증할 수 있습니다. 시간 비용이면 허용 이동 속도에 근거한 하한이 필요합니다. 포탈·배 같은 지름길은 단순 직선 거리/일반 이동 속도 휴리스틱의 하한 조건을 깨뜨릴 수 있습니다. 검증된 하한이 없으면 h=0으로 두어 Dijkstra와 같은 동작을 사용합니다. 위험 비용을 더할 때도 음수 보상은 사용하지 않습니다.

알고리즘 문헌: [Dijkstra, 1959](https://doi.org/10.1007/BF01386390), [Hart·Nilsson·Raphael, 1968](https://doi.org/10.1109/TSSC.1968.300136). 위 설계 선택은 해당 알고리즘의 조건을 이 프로젝트에 적용한 검토입니다.

## 안전 경로라고 부르기 위한 조건

적대/정예 몬스터 구역, 플레이어 레벨 차이, 진영/PvP, 낙하, 통행 제한을 **각각 출처와 갱신 시점을 가진 데이터**로 확보해야 합니다. 서버·페이즈·퀘스트 진행·다른 플레이어에 따라 위험이 바뀔 수 있습니다. 알려진 위험과 미확인 위험을 구분하고, 정보가 없는 간선의 위험을 0으로 처리하지 않습니다. 초기 제공 명칭은 ‘검증된 도로 경로’ 또는 ‘이동 거리 우선’이 적절하며, 위험 자료가 불충분한 상태에서 안전을 보장하지 않습니다.

## CPU·메모리 예산

예시로 노드 10,000개 × 16바이트, 간선 30,000개 × 12바이트의 **압축 데이터 설계**는 약 520,000바이트입니다. 이는 저장 형식의 산술 예시이며 Lua 런타임 메모리 측정값이 아닙니다. 실제 Lua 테이블/문자열·인덱스·힙·탐색 배열·캐시를 포함하면 더 커집니다. 선택 지역의 그래프만 필요할 때 로드하고, 인접 목록·정수 인덱스·재사용 탐색 배열을 검토합니다.

검색은 출발/목적지 또는 선택 조건이 바뀔 때만 수행합니다. 프레임마다 전체 그래프를 다시 탐색하지 않습니다. 장시간 검색은 프레임 예산과 최대 확장 수를 가진 취소 가능한 작업으로 나누고, 프로필/출발 조건이 바뀐 결과는 폐기합니다. 검색 없는 대기 상태의 상시 OnUpdate는 만들지 않습니다. 최초 시험판의 예산 후보는 프레임당 약 1ms, 전체 50,000회 노드 확장 상한이지만, **실제 저사양 클라이언트 측정 후 조정할 설계안**입니다.

| 방식 | 데이터·정확도 | 개발 난이도·성능 |
| --- | --- | --- |
| 이용자 수동 경유지 | 이용자가 통행 경로를 판단. 전 지역 도로 DB 불필요 | 현재 1.11.5.8 구현. 짧은 순서 목록만 관리 |
| 사전 제작 도로망 | 커버리지·버전·연결 검증이 핵심. 제한 지역부터 검증 가능 | 데이터 제작 부담 큼. 검색은 요청 시 한 번 수행 가능 |
| 실시간 도로망 생성 | 공개 위치만으로 장애물/층/미방문 도로를 판정할 수 없음 | 수집·동기화·오염 제거·메모리 부담 큼. 현재 자료로 완전 자동화 약속 불가 |

## 후속 개발 단계와 진입 조건

1. **현재 릴리스 검증:** 수동 경로의 저장, 경유지 순서, 거리 판정, 퀘스트 복귀, 실제 비용을 인게임 확인표로 검증합니다.
2. **데이터 소규모 조사:** 인접한 1~2개 지역의 도로·교차점·다리·산길·경계만 조사합니다. 출처/권한/클라이언트 빌드와 조사 일자를 기록합니다.
3. **그래프 검증 도구:** 끊긴 길, 단방향, 층 충돌, 금지 간선, 지역 전환, 출발/도착 연결을 검사합니다. 도로를 따라 실제 이동한 기준 경로와 비교합니다.
4. **Dijkstra 시험판:** 도보 경로만 요청 시 계산합니다. 최단 경로 기준 사례, 경로 없음, 검색 취소, 작업 예산을 검증하고 기존 안내로 결과를 전달합니다.
5. **A* 비교:** 하한을 증명한 휴리스틱만 추가합니다. 동일한 그래프에서 Dijkstra와 비용이 일치하는지 비교하고 실제 탐색 수/시간/메모리를 측정합니다.
6. **특수 이동:** 비행·배·포탈의 사용 조건/연결/시간을 확인한 뒤 별도 간선으로 추가합니다. 조건을 확인하지 못하면 제외합니다.
7. **위험 정보:** 충분한 실제 자료를 확보했을 때만 선택 가능한 회피 가중치를 추가합니다. 미확인 위험을 계속 표시하고 전체 안전을 보장하지 않습니다.

## API 조사 근거와 확인 수준

- [Forever Map API 명세](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/MapDocumentation.lua): 위치, 크기, 지도/world 변환 및 지도 연결 정보의 계약을 확인했습니다.
- [Forever TaxiMap API 명세](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/TaxiMapDocumentation.lua): 비행 지점 정보의 범위를 확인했습니다. 보행 도로망 제공 계약으로 해석하지 않았습니다.
- [Forever Minimap API 명세](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/MinimapDocumentation.lua): 표시 반경의 야드 단위를 확인했습니다.
- [Forever Line API 명세](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/SimpleLineAPIDocumentation.lua): 선언은 있으나 실제 클라이언트의 실행 가능성을 이번 작업에서 확인하지 못했습니다. 기존 Texture 풀 렌더링을 유지합니다.

Gethe 저장소는 공개 클라이언트 UI 소스의 보관본이며 현재 사용자 클라이언트의 실행 확인을 대신하지 않습니다. 플레이어 방향은 기존 GetPlayerFacing 호출을 재사용하고 반환값을 검증합니다. 공개 API 명세 확인·소스/모의 검사·실제 클라이언트 지원 확인을 구분합니다. **1.11.5.8의 실제 Forever 실행, 보호 실행/taint, 거리 정확도, 렌더링과 성능은 인게임 검증 필요**입니다.
