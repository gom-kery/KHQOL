## 상단 위치 잠금

기존 22개 컨트롤의 getter/setter와 원래 module/section/title/predicate를 헤더로 연결했습니다. 동일 본문 셀은 생성하지 않습니다. 검색은 원래 경로에서 고정 헤더를 강조합니다. 모듈 사용 아래 같은 X와 간격으로 잠금 ON/OFF를 직접 표시하며, 복수 행의 이름은 왼쪽에 표시합니다. 위치 편집 버튼은 아래에 남습니다. 설명 높이·행 이름 줄바꿈·행 수·편집 버튼으로 헤더와 본문 시작점을 함께 계산합니다.

단일/복수/공유 잠금과 실제 통계 ID는 HEADER-LOCKS.md에 모두 있습니다. 시계 3행, 자원/콤보 2행, 전문기술 버튼/목록은 공유 1행입니다. 예시와 달리 버프 감사 알림과 파티 버튼에는 원래 독립 잠금이 없어 만들지 않았습니다. 유닛/파티 루트, 대상 시전, 기본창/주사위/알림 등은 기존 전용 편집의 안전한 예외를 보존합니다.

경험치·환경·PvP·발동 HUD의 잠금은 현재 접속의 unlocked/moving 상태이며 좌표의 프로필 저장과 구별합니다. 미니맵은 계정 공용입니다. 다른 저장 잠금은 원래 프로필/레거시 정책을 그대로 사용합니다. 잠금 조작으로 좌표를 초기화하거나 배치 모드를 바꾸지 않습니다. 원래 잠금 callback에 현재 위치 저장/예시 표시가 포함된 경우는 그대로 실행합니다. 전투 제한/보류도 기존 callback과 module/Labs 조건을 사용합니다.

## 전문기술 상태·데이터

설정 위치는 기존 편의 기능 > 일반 편의 > 전문기술입니다. rankGuide.enabled=false, locations=true, notes=true 세 키만 새 기본값으로 보충합니다. 기존 false/true 값과 미지 필드를 보존합니다. 상위 안내는 전문기술 버튼 표시와 독립적입니다.

C_SkillInfo.GetSkillLineInfoByID의 공개 rank/maxRank를 우선 읽고 기존 GetProfessions/GetProfessionInfo 조회 캐시와 응급치료 fallback을 재사용합니다. 두 API의 기본 숙련과 별도 보정값을 혼합하지 않습니다. 알려진 상한으로 배운 tier를 판단하며 현재 수치가 높다고 tier를 건너뛰지 않습니다. 상한 도달 전에도 다음 단계를 보여 주고, 최종 확인/다른 상한/미지원 기술/읽기 불가를 구분합니다. 레벨·기본 숙련·공개 퀘스트 완료 플래그는 각각 충족 초록, 미충족 빨강, 미확인 중립으로 표시합니다.

첨부 문서와 WOWF 원문 12기술·48단계 및 NPC 234명, 책·퀘스트·비용을 대조했습니다. 0이나 $undefined로 직렬화되었더라도 화면/문서 미표기는 UNKNOWN입니다. 현재 recipeCatalog는 그대로이며 rankCatalog는 별도 정적 데이터입니다. SavedVariables에 복사하지 않습니다. 단계/조건과 전체 NPC 표는 RANK-DATA-VERIFICATION.md, 구조화된 증거는 Review의 research JSON에 있습니다.

## 표시 범위와 안전한 대안

조사한 Camelot CraftingPage.RankBar는 BACKGROUND 템플릿으로 입력을 강제로 켜지 않았습니다. 기존 bar 스크립트/입력/툴팁/크기/위치를 바꾸는 대신 오른쪽의 **KHQOL 소유 i 아이콘**을 사용합니다. 공개 접근 가능한 자체 제작 창·소유 기술에서만 표시하고 늦은 로드/열기/닫기/기술 전환에 갱신합니다. 전투 중에는 숨기고 종료 후 다시 연결합니다. 읽기 불가/연결/다른 플레이어 창에는 안내를 붙이지 않습니다.

별도 제작 창이 없는 채집/보조 기술과 native 영역을 확인할 수 없는 경우는 기존 전문기술 설정의 기술 선택+i와 기존 펼친 목록의 아이콘에서 안내/등록합니다. 기술을 새로 배운 것처럼 취급하거나 가짜 제작 창을 만들지 않습니다. 기본 제작/창 열기 버튼은 좌클릭 그대로이며 안내 ON의 우클릭만 등록 요청입니다. 프로필/숙련/레벨 변경을 이벤트로 합쳐 갱신하고, tooltip이 열린 채 기술이 바뀌면 새 정보로 교체합니다. Refresh를 조회로 재집계하지 않습니다.

## 지도·노트·안내

원문의 지역/도시 좌표와 uiMap label을 구별하여 연결했습니다. NPC 숫자 ID·외부 zone ID·atlas 투영점을 클라이언트 지도 ID로 쓰지 않습니다. 등록 직전에 C_Map.GetMapInfo의 정확한 ID/이름/Zone·City 종류가 맞아야 하며 백분율을 한 번 0~1로 변환합니다. 다른 언어/지도 변경/동명·다층 불일치/없음/secret은 등록을 거부합니다. 울다만 안노라는 던전 설명만 가능합니다. 이는 좌표 검증의 의도된 제한입니다.

우클릭 요청 후 유효 후보 1개는 바로 등록, 여러 개는 공통 메뉴에서 선택합니다. 현재 기술/상한/다음 단계/owner/profile generation/epoch 및 좌표를 다시 확인합니다. AddTodoCoordinate의 반환 항목이 실제 기존 노트 목록에 생성된 것을 확인한 후 완료를 기록합니다. 새 저장소·쉼표 파서·안내 엔진이 없습니다.

중복은 **같은 mapID와 0~1 X/Y의 차이 1e-7 미만**인 기존 노트가 있으면 재사용합니다. 같은 위치의 다른 메모도 보존하는 넓은 중복 정책이며 기술/단계/NPC가 같은 반복 등록도 포함합니다. 메모/완료/체크리스트를 덮어쓰거나 완료를 해제하지 않습니다.

등록 후 결과 메뉴에서 사용자가 ‘등록된 노트 위치 길 안내’를 선택해야 기존 pin route ticket/StartTodoPinGuidance를 호출합니다. 안내 시작 true일 때만 실행으로 기록합니다. 등록 자체는 해당 함수를 호출하거나 퀘스트 수동 목표를 설정하지 않습니다. 기존 노트의 자동 선택/autoAdvance가 켜져 있으면 기존 AddTodoCoordinate 동기화 정책은 그대로 적용됩니다. 노트 사용/안내 옵션은 강제로 켜지 않습니다. Quest Navigator 자동 목표 선택 코드는 수정하지 않았습니다. 안내 엔진은 코어+노트이므로 Quest Navigator/툴팁 애드온이 없어도 가능한 범위에서 동작하며 Clock/노트가 없으면 등록을 이유와 함께 막습니다.

## Usage·프로필·성능

기존 카탈로그의 **1559개 행**과 ID/종류/소유/바인딩을 보존했습니다. 잠금의 실제 변경은 기존 CommitSetting → UsageDiagnostics 한 경로입니다. Unlock은 Position Editor 시작이 아닙니다. Header Refresh/프로필 적용/재생성은 변경 입력이 아닙니다.

추가 설정 ID는 setting.professions.guide.enabled/locations/notes와 기존에 미계측이던 setting.buffReminder.locked입니다. 새 feature는 feature.profession.guide(실제 표시 구간), note_request(명시 요청), note_added(새 항목 생성), navigate(기존 안내 성공)입니다. 메뉴 열기·후보 선택·중복·실패를 완료로 기록하지 않습니다. 닫았다 다시 표시한 안내만 새 조회이며 Refresh는 0입니다. 노트 없는 구성은 완료/안내 capability를 제공하지 않습니다.

DevTools **0.3.1**은 카탈로그와 bridge phase 허용 목록을 추가했으며 Usage v0.1/schema 1/protocol 1을 유지합니다. 이전 로그·ID·버전 이력을 보존합니다. NPC/캐릭터 이름, 좌표, 숙련값, 메모를 진단에 전달하지 않습니다. 기록 OFF/미설치에서도 기능은 동작합니다. 정적 데이터/프레임/검사 결과는 런타임 객체에만 두며 새 OnUpdate·전체 기술 목록 반복 폴링은 없습니다. OFF는 자체 이벤트/예약/툴팁/메뉴/네이티브 아이콘을 정리합니다. 기존 전문기술 수집 이벤트는 변경하지 않았습니다.
