# 1.11.8.16 도안 습득 알림 위치 수정·검증

## 제보와 범위

사용자 확인: 도안 습득 알림의 크기는 변경되지만 공통 알림 저장 위치에 표시되지 않음.
기준: KHQOL 1.11.8.15 Full (`c065a96a1cd9fc15d239dcd316fd5261a93bd53ab325131825470b172757ae2a`).
결과: KHQOL 1.11.8.16, DevTools 0.3.0/Usage 0.1/schema 1/protocol 1 유지.

기존 코드는 공통 AlertFrame 루트 이동과 도안 풀의 크기 변경을 별도로 수행했습니다. 공통 부모가 위치 변경을 허용하지 않거나 도안의 앵커 연결이 이동한 부모를 우회하면 크기만 적용될 수 있었습니다. 접근 불가 루트를 둔 .15 모의 환경에서 130% 크기 적용·기본 위치 잔류를 재현했습니다. **이 조건이 사용자의 실제 클라이언트에서 최초 원인이었는지 추적한 것은 아닙니다.**

## 변경

- NativeAlerts.lua: 도안 활성 풀의 선두와 공통 루트의 공개 연결을 최대 32단계로 확인. 정상 스택은 그대로 유지.
- 저장 위치가 전달되지 않는 경우에만 안전하게 접근 가능한 선두 도안을 KHQOL 소유 위치 기준점에 연결. 다른 도안·후속 알림의 native 순서 유지.
- native UpdateAnchors 이후 위치 적용. 크기 100%에서도 동작하고 저장 위치/도안 배율 변경과 재사용을 처리.
- OFF/위치 초기화/기본 편집 모드/풀 반환 시 위치 소유권 정리. native가 비운 프레임에 과거 좌표를 되살리지 않음.
- 전투 중 쓰기 보류 후 최신 설정 적용. 보호/접근 불가 프레임은 건너뜀. 다른 기본 프레임을 옮길 수 없는 경우 설정 설명에 도안 적용 범위를 표시.
- Bootstrap/Campfire 버전 상수 및 DevTools를 제외한 18개 TOC를 .16으로 갱신. README/CHANGELOG/DESIGN/INSTALL-GUIDE에 이번 안내 추가.

저장 키·프로필·공통 위치 값·배율을 바꾸거나 초기화하지 않습니다. 알림을 직접 생성/재전송하거나 게임의 알림 설정을 강제로 켜지 않습니다. 클릭/표시/대기열/해제 원본을 교체하지 않고 주기적 폴링·OnUpdate·통계 저장을 추가하지 않았습니다. DevTools와 슬라이더 소스는 .15와 byte 동일합니다.

## 실제 게임 확인 — 전부 NOT TESTED

1. 기존 설정/공통 알림 위치를 유지하고 1.11.8.16으로 교체합니다.
2. 인터페이스 → 기본 UI → 알림에서 ‘기본 알림 위치·크기 변경’ ON과 저장 위치를 확인합니다. 검색의 ‘공통 알림 위치’로도 이동할 수 있습니다.
3. 먼저 크기 100%에서 새 도안을 습득해 저장한 예시 위치와 비교합니다. 다음 실제 습득에서 변경 크기(예: 130%)도 확인합니다.
4. 연속 습득할 때 두 도안이 겹치지 않고 차례대로 쌓이고 사라지는지 확인합니다. 클릭 시 기존 전문기술/해당 도안 열기 동작을 확인합니다.
5. 다른 기본 알림·주사위가 함께 표시되어도 그 크기와 원래 동작이 유지되는지 확인합니다.
6. 위치만 초기화하면 크기/ON은 유지되고, 전체 알림 설정 초기화는 기존 기본값으로 돌아가는지 확인합니다. 필요하면 기존 값을 먼저 기록합니다.
7. 정상 /reload 후 저장 위치가 유지되는지 확인합니다. 전투 중 변경은 종료 후 반영되는지 확인합니다.

설정이 게임에서 알림을 숨기도록 되어 있거나 프레임 접근이 허용되지 않으면 제한을 우회하지 않습니다. 재발 시 게임/애드온 버전·설정 크기·저장 위치와 실제 표시 화면을 함께 확인해야 합니다. 실제 사용자/테스터 기록을 이번 결과물에 넣지 않았습니다.
