# WoW Forever 인스턴스 던전 지도 — 위치 API 조사 및 인게임 검증 계획

## 현재 판정: D — 구현 보류

첫 실제 결과에서 `GetInstanceInfo()`는 성공했지만 `UnitPosition`, `C_Map.GetBestMapForUnit`, `C_Map.GetPlayerMapPosition`, `GetPlayerFacing`은 좌표/Map ID/방향값을 제공하지 않았습니다. 이는 해당 위치에서 방식 A의 근거가 없다는 뜻이며, 현재 판정은 유지합니다. DevTools `0.1.5`는 `nil`과 반환값 없음도 구분해 기록합니다. 실제 던전 안에서 이동·전투·재입장 결과를 추가로 받은 뒤 판정을 갱신합니다.

## 위치 API 조사표

| API | DevTools 확인 방식 | 던전 내 검증 상태 | 지도/층 연결 판단 |
| --- | --- | --- | --- |
| `UnitPosition("player")` | 존재 여부, 안전 호출, 모든 반환값 기록 | 미검증 | instance ID와 좌표가 안정적이고 이동에 따라 변하는지 필요 |
| `C_Map.GetBestMapForUnit("player")` | 존재 여부, 안전 호출, Map ID 기록 | 미검증 | Map ID가 던전 및 층을 구분하는지 필요 |
| `C_Map.GetPlayerMapPosition(mapID, "player")` | numeric Map ID가 있을 때 안전 호출, `GetXY()` 기록 | 미검증 | 이미지 좌표 보정에 쓸 수 있는지 여러 지점 비교 필요 |
| `GetPlayerMapPosition("player")` | 존재 여부, 안전 호출, 반환값 기록 | 미검증 | 구형 API의 지도 사전 설정 의존성 확인 필요 |
| `GetPlayerFacing()` | 존재 여부, 안전 호출, 방향값 기록 | 미검증 | 화살표 회전에는 사용할 수 있으나 위치 자체는 제공하지 않음 |
| `GetUnitSpeed("player")` | 존재 여부, 안전 호출, 속도값 기록 | 미검증 | 이동 추정 보조값일 뿐 절대 위치를 보장하지 않음 |
| `GetInstanceInfo()` | 존재 여부, 안전 호출, 모든 반환값 기록 | 미검증 | 던전명·유형·인스턴스 ID 및 입출장 감지의 후보 |

진단 화면의 **Combat** 값도 함께 기록합니다. 같은 API를 비전투·전투·전투 종료 뒤에 비교하여 전투 중 호출 가능 여부와 값 변화를 확인합니다.

## DevTools 사용법

1. `/khqoldev position` 또는 `/khqoldev`를 입력하고 **Position** 탭을 엽니다.
2. **Snapshot & Copy**로 현재 API 존재 여부와 단일 호출 결과를 즉시 복사합니다.
3. 이동 테스트에서는 **Start Sampling**을 누릅니다. 이때에만 1초 간격으로 위치 API를 호출합니다.
4. 정해진 지점까지 이동한 후 **Stop Sampling**을 누릅니다.
5. **Copy Full Report**를 눌러 전체 보고서를 Ctrl+C로 복사해 전달합니다.
6. **Limit** 버튼으로 샘플 상한을 10/30/60/120개 중 선택합니다. 한도를 초과하면 가장 오래된 샘플부터 제거됩니다.

진단은 KHQOL 원본의 Quest Navigator, 지도 UI, 프로필 및 SavedVariables를 읽거나 수정하지 않습니다. 테스트를 멈추면 위치 샘플링도 즉시 중지됩니다.

## 인게임 테스트 절차

### 1. 던전 밖

- 가만히 서서 Snapshot을 1회 기록합니다.
- 앞으로, 뒤로, 좌우로 각각 약 5초 움직이며 Sampling 보고서를 기록합니다.
- 제자리에서 회전하며 `GetPlayerFacing()` 변화를 기록합니다.

### 2. 던전 입구

- 입장 직전, 입장 직후, 입구에서 이동 후 각각 Snapshot을 복사합니다.
- `GetInstanceInfo`, `UnitPosition`의 instance ID, Map ID가 어떻게 달라지는지 비교합니다.

### 3. 던전 내부

입구, 첫 갈림길, 첫 보스 근처, 다른 구역 또는 층에서 각각 Sampling을 시작·정지하고 Full Report를 저장합니다. 좌표/Map ID/instance ID가 이동과 구역 전환에 일관되게 변화하는지 확인합니다.

### 4. 전투

같은 위치에서 비전투, 전투, 전투 종료 직후에 Snapshot을 각각 기록합니다. 오류·보호값·nil·변화한 값을 모두 그대로 보고합니다.

### 5. 재입장 및 재접속

가능하면 같은 지점에서 재입장, `/reload`, 인스턴스 재생성, 재접속 전후 결과를 비교합니다. 동일한 물리 위치가 같은 좌표/Map ID 체계로 돌아오는지 확인합니다.

## 결과 기록 양식

```text

테스트 시점: 입구 / 갈림길 / 보스 / 층 이동 / 전투 등

<여기에 Copy Full Report 전체 붙여넣기>
```

## 세 가지 구현 방식의 판정 조건

### A — 실시간 좌표 기반 지도

`UnitPosition` 또는 `C_Map.GetPlayerMapPosition`이 던전 안에서 안정적으로 값을 반환하고, 여러 기준점의 좌표가 이동에 따라 일관되게 달라져야 합니다. 그 뒤 지도 이미지의 최소 3개 기준점으로 원점·축 방향·회전·스케일을 보정해야 합니다. Map ID 또는 동등한 값으로 층을 구분할 수 있어야 층별 자동 전환도 가능합니다. 이 모든 조건을 실제 결과로 충족할 때만 A로 판정합니다.

### B — 이동 정보 기반 위치 추정

방향과 속도만 있으면 수동 시작점에서 이동량을 적분할 수는 있습니다. 그러나 후진·횡이동·점프·낙하·넉백·순간이동·서버 보정은 큰 누적 오차를 만들며, 실제 좌표와 동일하게 취급할 수 없습니다. 주기적인 기준점 재보정 없이는 실용적인 정확도를 기대하기 어렵습니다.

### C — 진행 구역 기반 지도

자동 좌표가 불가능해도 `GetInstanceInfo`로 던전을 식별하고, 보스 진행/수동 구역 선택/주요 갈림길을 이용해 정적 지도와 경로를 제공할 수 있습니다. 층 전환은 자동 식별 근거가 없으면 사용자가 수동으로 선택해야 합니다. 이는 자동 플레이어 점 표시가 아닌 안내 지도입니다.

## 향후 KHQOL 던전 지도 v0.1 권장 사양

실제 결과가 A 조건을 충족한 경우에만 다음 최소 범위를 권장합니다: 던전별 정적 이미지 1장, 수동 보정 기준점 3개 이상, 현재 위치 점·방향 화살표, 0.5~1초 갱신, 층별 Map ID 매핑, 좌표 미지원 시 명확한 비활성 안내. 좌표 결과가 부족하면 지도 UI를 먼저 구현하지 말고 C 방식의 구역·보스·갈림길 안내부터 별도 범위로 검토하는 편이 안전합니다.
